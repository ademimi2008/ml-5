# Практическая работа № 5. Классификатор и анализ метрик

Бинарная классификация (логистическая регрессия) с анализом качества и подбором порога под заданную цену ошибки.

## Цель

Построить модель бинарной классификации и провести анализ качества с учётом цены ошибки: ложноположительный (FP) и ложноотрицательный (FN) результаты считаются неравноценными.

## Запуск

1. Установите зависимости:
   ```
   pip install numpy pandas matplotlib scikit-learn jupyter
   ```
2. Положите CSV-файл с данными рядом с ноутбуком.
3. В первой ячейке ноутбука задайте настройки:
   ```python
   CSV_PATH = "data.csv"   # путь к данным
   TARGET = "target"       # имя целевого столбца (0/1)
   COST_FP = 1.0           # цена ложноположительного
   COST_FN = 10.0          # цена ложноотрицательного
   ```
   Если `CSV_PATH = None`, используются синтетические данные.
4. Выполните все ячейки (Run All).
5. Перепишите блок «Вывод» под свои результаты.

Если целевой столбец содержит не 0/1, а, например, «yes»/«no», добавьте после загрузки `y = (y == "yes").astype(int)`. Для категориальных признаков добавьте `X = pd.get_dummies(X)`.

## Ход работы

### 1. Данные и разбиение

Выборка делится на train, val и test со стратификацией по классу. Порог подбирается на val, итоговые метрики считаются на test, поэтому утечки данных нет.

### 2. Модель

`StandardScaler` и `LogisticRegression` в одном `Pipeline`. Вместо жёстких меток используются вероятности класса 1 (`predict_proba`).

### 3. ROC и PR кривые

![ROC и PR кривые](roc_pr.png)

AUC не зависит от порога и показывает, насколько хорошо модель ранжирует объекты по вероятности. При дисбалансе классов PR-кривая информативнее ROC: она учитывает precision и сравнивается с базовым уровнем, равным доле положительного класса.

### 4. Подбор порога

Суммарная цена ошибок:

```
cost = COST_FP · FP + COST_FN · FN
```

Теоретический ориентир для порога: `COST_FP / (COST_FP + COST_FN)`. При 1 : 10 это около 0,09. Перебор порогов на валидации даёт то же значение.

![Выбор порога](threshold_cost.png)

### 5. Сравнение на тесте

| Порог | Accuracy | Precision | Recall | F1 | FP | FN | Цена ошибок |
|---|---|---|---|---|---|---|---|
| 0,5 | 0,822 | 0,667 | 0,285 | 0,399 | 37 | 186 | 1897 |
| 0,09 | 0,502 | 0,287 | 0,942 | 0,440 | 608 | 15 | 758 |

![Матрицы ошибок](confusion_matrices.png)

## Выводы (для синтетических данных)

- **Метрика.** Если FN дороже FP, главная метрика — recall при приемлемой precision. Accuracy при дисбалансе вводит в заблуждение: при пороге 0,5 она высокая (0,82), но модель пропускает около 70% положительных объектов.
- **Порог.** Снижение порога с 0,5 до 0,09 подняло recall с 0,29 до 0,94 и уменьшило цену ошибок в 2,5 раза.
- **Цена компромисса.** Выросло число ложных тревог (FP: 37 → 608), упали precision и accuracy. При заданной цене ошибки это оправдано.
- **Равные цены.** Если FP и FN равноценны, можно оставить порог 0,5: оснований смещать порог нет.
